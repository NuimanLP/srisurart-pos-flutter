```
## ที่เก็บและการตั้งชื่อ
- โฟลเดอร์: `handoff_log/` (ถ้ายังไม่มี ให้สร้าง)
- ไฟล์: `handoff_<หัวข้อสั้น-kebab-case>_<DD_MM_YYYY>.md`
- ใช้วันที่วันนี้แบบเต็ม และ **ห้ามใช้คำว่า "เมื่อวาน / สัปดาห์ที่แล้ว / เร็ว ๆ นี้"**
  ที่ไหนก็ตามในไฟล์ ให้เขียนวันที่จริงเสมอ เพราะคนอ่านจะมาอ่านอีกทีตอนไหนก็ไม่รู้
- **ห้ามทับไฟล์เดิมเด็ดขาด** ถ้าชื่อชนให้เติม `_2`, `_3`
- อัปเดต `handoff_log/INDEX.md` เพิ่ม 1 บรรทัด (ถ้ายังไม่มีไฟล์ ให้สร้าง):
  `- YYYY-MM-DD — [หัวข้อ](ชื่อไฟล์.md) — สรุป 1 ประโยค — สถานะ`

## หลักสำคัญที่สุด
**เขียนเฉพาะสิ่งที่จะหายไปถ้าไม่จด**
อะไรที่คนมาอ่านทีหลังเปิดไฟล์/ข้อมูลดิบ/ประวัติเองได้ ไม่ต้องลอกมาซ้ำ
สิ่งที่ต้องจดคือ **เหตุผลเบื้องหลัง**, **ทางที่ลองแล้วตัน**, และ **สิ่งที่ยังไม่รู้**

## โครงไฟล์ — ใช้หัวข้อเหล่านี้ ตามลำดับนี้

# Handoff — <หัวข้อ> (<YYYY-MM-DD>)

**วันที่:** … · **ผู้บันทึก:** … · **สถานะ:** กำลังทำ / ติดอยู่ / รอคนอื่น / ปิดแล้ว
**ขอบเขต:** งานนี้ครอบคลุมอะไร 1 บรรทัด
**ต่อจาก:** ลิงก์ handoff หรือเอกสารก่อนหน้า (ถ้ามี)

## 1. ตอนนี้อยู่ตรงไหน
สถานะจริง ณ วันที่บันทึก — ถ้ามีคนมารับช่วงต่อพรุ่งนี้ เขาจะเจอสภาพแบบไหน

## 2. รอบนี้ทำอะไรไป ได้ผลอะไร
เรียงตามลำดับ ระบุ**ผลลัพธ์จริง** ไม่ใช่แค่ "ทำแล้ว"
มีตัวเลข/หลักฐาน/ค่าที่วัดได้ ให้ใส่ค่าจริง

## 3. ตัดสินใจอะไรไปบ้าง เพราะอะไร
ทางเลือกที่มี → เลือกอันไหน → เหตุผล → ใครเป็นคนตัดสิน
**นี่คือส่วนที่หายเร็วที่สุด ห้ามข้าม** อีก 3 เดือนจะจำไม่ได้ว่าทำไมถึงเลือกทางนี้

## 4. ลองแล้วไม่เวิร์ก (ทางตัน)
สิ่งที่พิสูจน์แล้วว่าผิด ใช้ไม่ได้ หรือไปต่อไม่ได้ + **เพราะอะไร**
เพื่อไม่ให้คนถัดไป (หรือตัวเองในอีก 2 เดือน) เสียเวลาลองซ้ำ

## 5. ยังไม่ชัวร์ / สมมติฐานที่ยังไม่พิสูจน์
แยกให้ชัดว่าอันไหน **ยืนยันแล้ว** อันไหน **แค่เดา**
ถ้าอ้างอะไรที่ยังไม่ได้ตรวจสอบ ให้เขียนกำกับตรง ๆ ว่ายังไม่ได้ตรวจ

## 6. ก้าวถัดไป (เรียงลำดับ)
เขียนเป็นข้อ ๆ ที่ลงมือทำได้จริง ข้อละ 1 การกระทำ
ข้อไหนต้องรอคน/รอของ/รอผล ให้ระบุว่ารออะไรและรอจากใคร

## 7. ข้อควรระวัง
กับดักที่เพิ่งเจอ · ของเปราะที่ห้ามไปแตะ · ข้อจำกัดที่ต้องรู้ก่อนทำต่อ

## 8. อ้างอิง
ไฟล์ · เอกสาร · ลิงก์ · เลขหน้า · ชื่อคนที่ต้องถาม

## กติกาการเขียน
- **ห้ามแต่งเติม** สิ่งที่ไม่ได้เกิดขึ้นจริงในเซสชันนี้ ไม่รู้ให้เขียนว่าไม่รู้
- หัวข้อไหนไม่มีเนื้อหา ให้เขียนว่า "ไม่มี" **อย่าลบหัวข้อทิ้ง** (ช่องว่างก็เป็นข้อมูล)
- กระชับ อ่านจบใน 3 นาที ตัดคำเยิ่นเย้อ ใช้ bullet มากกว่าย่อหน้ายาว
- ถ้าเนื้อหาส่วนไหนยาวเกิน ให้แยกไปไฟล์ย่อยแล้วลิงก์จากที่นี่

[ตั้งค่า]
- ภาษา: ไทยผสมศัพท์เทคนิคอังกฤษ
- ชื่อผู้บันทึก: <ชื่อคุณ คุณทำส่วนไหน>
- หัวข้อของ handoff รอบนี้: <ใส่หัวข้อ หรือปล่อยว่างให้ AI ตั้งเอง>
```

## วิธีปรับใช้ตามสายวิชา

| สาย | หัวข้อที่ควรเพิ่ม |
|---|---|
| งานวิจัย / แล็บ | เพิ่มใต้ §2: **สภาวะการทดลอง** (อุปกรณ์ ล็อตสารเคมี อุณหภูมิ ผู้ทำ) — ผลซ้ำไม่ได้มักเพราะตรงนี้ |
| ธีสิส / เขียนเปเปอร์ | เพิ่ม §3.1: **ข้อคิดเห็นอาจารย์ที่ปรึกษา** แยกจากการตัดสินใจของตัวเอง |
| วิศวกรรม / ซอฟต์แวร์ | เพิ่มใต้ §2: **ตรวจสอบด้วยอะไร** (test/measurement + ค่าที่ได้) |
| ออกแบบ / สถาปัตย์ | เพิ่ม §4.1: **แบบที่ถูกตีตก** + เหตุผล |
| ธุรกิจ / กฎหมาย | เพิ่ม §6.1: **เดดไลน์และผู้รับผิดชอบ** ต่อแต่ละข้อ |
| การแพทย์ / คลินิก | ⚠️ ห้ามใส่ข้อมูลระบุตัวผู้ป่วย ใช้รหัสแทน และเพิ่ม §0: **ขอบเขตความยินยอม** |
