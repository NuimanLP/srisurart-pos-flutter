> ## ✅ มติเจ้าของ 2026-10-26: **ไม่ย้ายข้อมูล — Pi เริ่มร้าน `001` ว่าง ๆ**
>
> เลือกก่อนว่าจะ B แล้วเปลี่ยนเป็น **ไม่ migrate อะไรเลย**: ไม่ dump `mob04`, ไม่นำเข้า backup ของแอป offline, ไม่ซ้อมนำเข้า
> (ร้านซ้อม `rehearsal` ไม่ได้ถูกสร้าง — ยกเลิกก่อนใส่รหัส) · หมวด 2–4 ด้านล่างเก็บไว้เป็นทางเลือกถ้าวันหลังอยากนำเข้า
>
> **ผล:** สินค้า/สต็อก/ราคา/ลูกค้า/ช่าง/ยอดเครดิตช่าง/supplier ต้อง**กรอกใหม่บน Pi** · เลขบิลเริ่มนับใหม่ ·
> ประวัติขายเดิมอยู่ในแอป offline (ห้ามลบจนกว่าเจ้าของไม่ต้องการ) · บิลทดลองบน `mob04` ทิ้ง
>
> **วันย้าย (ทำตามนี้แทนหมวด 3):**
> 1. จอง DHCP ให้ Pi ที่ router ร้าน → เสียบ Pi + HDD (ไฟ: adapter 27 W ทางการดีสุด) → รอ boot + Tailscale ขึ้น
> 2. PC: `wsl -d Ubuntu -- bash /mnt/d/Beestation/Sri_POS/ops/pi5-change-lan-ip.sh <IP ร้าน>` → ต้องจบ `DONE` + ready 200 ทั้ง LAN และ Tailscale
> 3. เครื่องในร้าน: เบราว์เซอร์ `https://<IP ร้าน>` (ติดตั้ง `frontend/assets/certs/pos-ca-pi5.crt` เป็น trusted root) หรือ APK
>    (`apk-pi5-*` ต้องมี Tailscale บนเครื่อง · เครื่องใน LAN ร้าน: `gh workflow run android-apk.yml --ref main -f target=pi5 -f server_url=https://<IP ร้าน>` หลังขั้น 2)
> 4. login ร้าน `001` ด้วย owner → ลงทะเบียนเครื่อง (enrolCode) → กรอกสินค้า/ลูกค้า/ช่าง → เปิดกะ → ขายบิลแรก
> 5. คืนนั้น: `backup-cron.log` จบ `(local + offsite)` = ขึ้น Google Drive
> 6. แอป offline: เลิกใช้ขาย แต่**ไม่ลบ** · `mob04`: เจ้าของตัดสินภายหลัง (เดโม/สำรอง/คืน VM)

## 3. ขั้นตอน (ทาง B)

### 3.0 ซ้อม — ก่อนวันจริง ไม่แตะร้านจริง

1. ขอไฟล์ backup จากแอป offline ที่ร้าน (ตั้งค่า → 💾 สำรอง/กู้คืน → ดาวน์โหลดไฟล์ backup) — แอป offline ให้ไฟล์ `.json` (`exportSnapshot`, รูปแบบ `sa_*` + `__meta`); ฝั่ง API รับ `.json` ≤ 10 MB (ไม่มีรูป) หรือ `.zip` ≤ 200 MB
   · 🔴 ไฟล์มีข้อมูลส่วนตัวลูกค้า/ช่าง: เก็บใน `D:\Beestation\Sri_POS\ops\secrets\` เท่านั้น ห้าม commit/แชต
2. บน Pi สร้าง **ร้านซ้อม** (platform-ui `http://localhost:13200` ผ่าน tunnel) เช่น code `rehearsal` → ลงทะเบียนเครื่องทดสอบ 1 เครื่อง (เบราว์เซอร์ PC ผ่าน Tailscale หรือ APK `apk-pi5-*`)
3. ในร้านซ้อม: ตั้งค่า → สำรอง/กู้คืน → **กู้คืนข้อมูล** เลือกไฟล์ข้อ 1 → รอ job จบ
4. ตรวจ (ทำเป็นตาราง): จำนวนสินค้า/ลูกค้า/ช่าง/supplier ตรงกับแอปที่ร้าน · สต็อก 10 รายการสุ่มตรง · ยอดเครดิตช่างตรง ·
   `doc_counters` สูงกว่าเลข RC/CN/PO/QT ล่าสุดในไฟล์ (ขาย 1 บิลทดสอบ → เลขบิลต่อจากเดิม ไม่ชน `409 RECEIPT_NO_CONFLICT`) ·
   (ไฟล์ `.json` ไม่มีรูปสินค้า — รูปต้องถ่ายใหม่บน API build)
5. จับเวลานำเข้า (ใช้วางแผนช่วงปิดร้าน) · จด error ทุกตัว
6. ลบร้านซ้อม (platform-ui หรือแบบเดียวกับการลบ `loadtest-tenant` ใน `session-2026-10-26-pi5-load-test.md`) +
   ไฟล์ pre-import ใน volume `exports` ของร้านซ้อม
7. ผ่านทุกข้อ → นัดวันจริง · ไม่ผ่าน → แก้ก่อน (เป็น PR แยก)

### 3.1 ก่อนวันจริง

- Pi อยู่ที่ร้านแล้ว + รัน `ops\pi5-change-lan-ip.sh <IP ร้าน>` (จอง DHCP ก่อน) · ทดสอบเครื่องในร้านเปิด `https://<IP ร้าน>` ได้
- แจก APK ให้เครื่อง Android ของร้าน: ถ้าเครื่องอยู่ใน LAN ร้าน **build APK ที่ชี้ IP ร้าน** (ต้องเพิ่ม `target` ใน `android-apk.yml` หรือรับ URL เป็น input — งาน PR เล็ก) ·
  `apk-pi5-*` ปัจจุบันชี้ Tailscale IP = ทุกเครื่องต้องลง Tailscale (เหมาะกับเครื่องนอกร้าน)
- ติดตั้ง CA ของ Pi (`frontend/assets/certs/pos-ca-pi5.crt`) ใน PC เคาน์เตอร์ ถ้าใช้เบราว์เซอร์
- backup Pi รอบล่าสุดขึ้น Drive สำเร็จ (`backup-cron.log` จบ `(local + offsite)`)

### 3.2 วันจริง (ตอนร้านปิด)

1. แอป offline ที่ร้าน: ปิดกะ → **ดาวน์โหลดไฟล์ backup `.json`** (ไฟล์สุดท้าย = ความจริงเดียว) · จดตัวเลขตรวจ: จำนวนสินค้า, มูลค่าสต็อก, เลขบิลล่าสุด
2. Pi: ร้าน `001` → ลงทะเบียนเครื่อง owner → **กู้คืนข้อมูล** ไฟล์ข้อ 1 (ร้านว่าง = ไม่ต้อง `mode=replace`)
3. ตรวจตามข้อ 3.0(4) กับตัวเลขข้อ 1 — **ไม่ตรง = หยุด** ร้านใช้แอป offline ต่อ (ไม่มีอะไรเสีย)
4. ตรงทั้งหมด → ลงทะเบียนเครื่องอื่นของร้าน (enrolCode) · ขายบิลแรก · พิมพ์ใบเสร็จ
5. รัน `backup-db.sh` บน Pi ด้วยมือ 1 รอบ → ยืนยันขึ้น Drive
6. แอป offline: **เลิกใช้ขาย** แต่ห้ามลบข้อมูล/ถอนแอป จนพ้นช่วงสังเกต (rollback)

### 3.3 หลังวันจริง

- 14 วันแรก: ดู Discord alert + `backup-cron.log` ทุกวัน · ปิดงวดเดือนแรกบน Pi (เลขเอกสารอิงงวด)
- `mob04`: ไม่ใช่ production อีกต่อไป → owner ตัดสินว่าเก็บเป็นเดโม/สำรอง หรือคืน VM (หมวด 5 ข้อ 5) · หยุดดึง backup รายวันของ mob04 ถ้าเลิกใช้
- อัปเดต README / `docs/status.md` / `07_CICD_DEPLOY.md §5` ว่า production = Pi · ตัดสินเรื่อง CD ไป Pi (ตอนนี้ deploy มือ)

## 4. Rollback

| ล้มตอนไหน | ทำอย่างไร |
|---|---|
| ก่อนขายบิลแรกบน Pi | ร้านใช้แอป offline ต่อทันที — ข้อมูลไม่ได้ย้ายออกจากแอป ไม่มีอะไรเสีย |
| หลังขายบน Pi ไปแล้ว | export backup จากร้าน `001` บน Pi (ZIP) → นำเข้ากลับแอป offline (`importLegacyBackup`, ทางเดียวกับ Phase-2 data migration ใน CLAUDE.md) **[ต้องยืนยันว่ารูปแบบไฟล์ API → แอป offline นำเข้าได้ — ซ้อมก่อนถ้าจะพึ่งทางนี้]** · หรือบันทึกบิลช่วงนั้นด้วยมือ |
| Pi เสีย (ฮาร์ดแวร์) | Pi ใหม่/เครื่องอื่น: `host-setup.sh` → provision → deploy SHA เดิม → กู้จาก Drive (`restore-db.sh`, ซ้อมแล้ว 2026-10-25) |

## 5. เจ้าของต้องตัดสิน

1. **ทางเลือก A / B / C** (แนะนำ B) — และยืนยันว่าบิล 16 ใบบน mob04 เป็นบิลทดลอง ไม่ต้องเก็บ

5. **mob04 หลังย้าย** — เดโม/สำรอง/คืน VM
