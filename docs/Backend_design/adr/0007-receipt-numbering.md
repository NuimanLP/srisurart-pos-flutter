# ADR-0007 — เลขเอกสารแบบเรียงต่อเครื่อง รีเซ็ตรายเดือน

* **สถานะ:** Accepted — 2026-09-04
  ⚠️ **ต้องให้เจ้าของร้านเห็นตัวอย่างใบเสร็จจริงก่อนพิมพ์ใบแรก** — ADR นี้ปลดล็อกให้เริ่ม
  implement ได้ แต่ไม่ได้แทนการยืนยันหน้าตาใบเสร็จ
* **ปิดข้อค้าง:** `00_INDEX.md` "ตัดสินใจแทนไม่ได้" ข้อ 1 / `04_QA_SCRUTINY.md` ข้อ 1
* **เกี่ยวข้อง:** `01_DATABASE.md §7.2`, ADR-0004 (device roles), `CONTRACT.md §7` (`docNo()`)

## การตัดสินใจ

เปลี่ยนจาก `docNo(prefix)` แบบสุ่ม (`RC12345678ABCD`) เป็น **เลขเรียงต่อเครื่อง รีเซ็ตรายเดือน**

```
RC01-2569-08-0042
│ │  │       │
│ │  │       └── ลำดับในเดือนนั้นของเครื่องนั้น 4 หลัก (0001..9999)
│ │  └────────── พ.ศ.-เดือน  = doc_counters.period
│ └───────────── device_no ซีโร่แพด 2 หลัก
└─────────────── prefix ตาม doc_type: RC ใบเสร็จ / CN ใบลดหนี้ / PO ใบสั่งซื้อ / QT ใบเสนอราคา
```

### ⚠️ แก้จากตัวอย่างในเอกสารเดิม: `device_no` ต้องซีโร่แพด 2 หลัก

`01_DATABASE.md §7.2` เขียนตัวอย่างเป็น `RC1-2569-08-0042` — **ใช้ไม่ได้** เพราะ
`devices.device_no` เป็น 1..99 ถ้าไม่แพด เครื่องที่ 1 กับเครื่องที่ 12 จะอ่านกำกวม
(`RC1-` กับ `RC12-` ต่างกันแค่ตัวคั่น พาร์สย้อนกลับพลาดง่าย) → ใช้ `RC01`, `RC12` เสมอ

## ใครออกเลข

คงตามข้อสรุปเดิมใน §7.2: **เครื่องเป็นคนออกเลข server ไม่ออกให้**
(ถ้า server ออก = ออฟไลน์ออกบิลไม่ได้ = ตัดความสามารถออฟไลน์ทิ้งทั้งหมด)

* counter อยู่ใน Drift ของเครื่อง ต่อ `(device_no, doc_type, period)`
* server เก็บ high-water mark ใน `doc_counters` + บังคับ `UNIQUE (tenant_id, receipt_no)`
* ✅ **สอดคล้องกับ ADR-0004** — เครื่องที่ออกเลขใบเสร็จได้คือเครื่อง `role='pos'` เท่านั้น
  และเครื่องแทนที่ต้องได้ `device_no` ใหม่ ไม่ใช้เลขเดิมซ้ำ → ชุดเลขไม่มีวันชนกัน

## 🔴 ช่องพังที่ต้องปิดตั้งแต่วันแรก: counter ในเครื่องหายได้

แอปรันบน **Flutter Web** — Drift เก็บใน IndexedDB/OPFS ซึ่ง **ผู้ใช้หรือเบราว์เซอร์ล้างได้**
(ล้างข้อมูลเว็บไซต์, เปลี่ยนเบราว์เซอร์, โหมดส่วนตัว, ลง Windows ใหม่)

ถ้า counter รีเซ็ตเป็น 0 → เลขที่ออกใหม่จะ**ชนกับใบเสร็จเดิมทั้งเดือน** →
`UNIQUE (tenant_id, receipt_no)` เด้งทุกบิล → **ขายไม่ได้เลยจนกว่าจะมีคนแก้ให้**

**ต้องมี 2 อย่างนี้ ไม่ใช่ทางเลือก:**

1. **seed counter จาก server ทุกครั้งที่เปิดแอป/ล็อกอิน** — `GET /doc-counters` คืน high-water
   mark ของ `(device_id, doc_type, period)` แล้วตั้ง `local = max(local, server)`
2. **ชน UNIQUE แล้วต้องขยับเลขแล้วลองใหม่ ห้ามให้บิลตก** — เป็นตาข่ายชั้นสุดท้าย
   ลูกค้ายืนรออยู่หน้าเคาน์เตอร์ บั๊กเรื่องเลขที่ต้องไม่ทำให้ขายไม่ได้

## ผลที่ตามมา

* ต้องเพิ่ม `GET /doc-counters` เข้า API catalogue (`02_API_SCREENS.md §4`) — ยังไม่มี
* **ห้ามแก้เลขของบิลเก่า** — บิลที่ import มาจากแอปเดิมยังเป็น `RC12345678ABCD` ต่อไป
  ทั้งสองรูปแบบอยู่ร่วมกันได้ เพราะ `UNIQUE (tenant_id, receipt_no)` ไม่สนรูปแบบ
  → ต้องบอกร้านว่า "บิลก่อนวันขึ้นระบบเป็นเลขแบบเก่า" ไม่ใช่บั๊ก
* **ตรวจเลขขาดช่วงได้แล้ว** — high-water mark เทียบกับจำนวนบิลจริงในเดือนนั้น
  ช่องว่าง = บิลหาย/เครื่องพัง ควรทำเป็นรายงานให้ owner เห็น (ของใหม่ที่แอปเดิมไม่มี)
* 4 หลัก = 9,999 บิล/เดือน/เครื่อง — เกินพอ แต่ต้องมี guard ว่าถ้าเกินให้ error ชัด ๆ ไม่ใช่วนกลับ 0001
* `CONTRACT.md §7` (`docNo()`) ต้องอัปเดต — ปัจจุบันผูกรูปแบบเดิมไว้เป็นสเปค
