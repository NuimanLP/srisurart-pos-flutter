# ADR-0008 — เก็บต้นทุน ณ วันที่ขายไว้ในบรรทัดบิล (`sale_items.cost_at_sale`)

* **สถานะ:** Accepted — 2026-09-04
* **ผู้ตัดสิน:** เจ้าของโปรเจกต์
* **ปิดข้อค้าง:** `01_DATABASE.md §11` แถว "`sales` ไม่เก็บ `cost` ตอนขาย"

## บริบท — นี่ไม่ใช่แค่ช่องว่างของ design อนาคต มันผิดอยู่บนจอร้านตอนนี้

`sale_items` ไม่มีคอลัมน์ต้นทุน (ทั้งใน Drift ปัจจุบันและใน DDL ของ PostgreSQL)
รายงานกำไรจึงต้องไปดึง **`products.cost` ปัจจุบัน** มาคำนวณย้อนหลัง

แต่ `receivePO` คิด **ต้นทุนเฉลี่ยถ่วงน้ำหนักใหม่ทุกครั้งที่รับของ** (`01_DATABASE.md §7.4`)
→ **พอรับของล็อตใหม่ที่แพงขึ้น กำไรของบิลเดือนที่แล้วก็เปลี่ยนตามย้อนหลัง**
ตัวเลข "กำไร" ของอดีตจึงขยับได้เรื่อย ๆ ตามการซื้อของในอนาคต

### สภาพปัจจุบันในแอป — สองที่ ไม่ตรงกัน

| ที่ | พฤติกรรม |
|---|---|
| CSV export (`settings_screen.dart:1625, 1802`) | ✅ **บอกตรง ๆ** — `'กำไร (ไม่รวม VAT, ต้นทุนปัจจุบัน)'` และ *"ต้นทุน/กำไรคำนวณจากต้นทุนปัจจุบัน ไม่ใช่ ณ วันที่ขาย"* |
| หน้าจอ "กำไรเดือนนี้" (`products_screen.dart:2843–2859`) | ❌ ขึ้น KPI คำว่า **"กำไรสุทธิ"** เฉย ๆ **ไม่มีหมายเหตุใด ๆ** เจ้าของร้านอ่านแล้วเชื่อว่าเป็นตัวเลขจริง |

### 🔴 บั๊กซ้อนอีกชั้น: กำไรถูกโป่งขึ้น ไม่ใช่แค่คลาดเคลื่อน

```dart
final costByPart = {for (final p in _products) p.partNo: p.cost};
final unitCost = costByPart[i.partNo] ?? 0;      // ← ตรงนี้
```
สินค้าที่ถูกลบไปแล้ว หรือถูกแก้รหัสอะไหล่ → หาไม่เจอ → **ต้นทุน = 0 → กำไร 100%** เงียบ ๆ
ยิ่งร้านทำความสะอาดรายการสินค้ามากเท่าไหร่ กำไรที่โชว์ยิ่งสูงเกินจริง

คอมเมนต์ในโค้ดระบุเองว่าแอป JS เดิมเป็น `i.cost ?? products.find(...).cost ?? 0`
— **แอปเดิมมี `i.cost` บนบรรทัดบิล ตอน port มา Flutter คอลัมน์นั้นหายไป** เหลือแต่ทาง fallback

## การตัดสินใจ

**เพิ่ม `sale_items.cost_at_sale NUMERIC` — snapshot ต้นทุน ณ วินาทีที่บันทึกการขาย**

* เขียนค่าใน **ทรานแซกชันเดียวกับ `saveSale`** (อ่าน `products.cost` ตอนตัดสต็อกอยู่แล้ว)
* **บิลเก่าที่ import มาเป็น `NULL`** — ไม่ backfill
* รายงานที่ครอบช่วงเวลาที่มี `NULL` **ต้องบอกผู้ใช้ว่าช่วงนั้นเป็นค่าประมาณ** (คำนวณจากต้นทุนปัจจุบัน)
* หลักการเดียวกับ `sale_items.name` / `price` ที่ denormalize ไว้อยู่แล้ว: **บิลคือเอกสารประวัติศาสตร์
  ต้องไม่เปลี่ยนตามข้อมูลหลักที่แก้ทีหลัง**

## ✅ ลงมือแล้ว (2026-09-04) — ฝั่ง Drift เสร็จ

* `SaleItems.costAtSale` (nullable) + `Customers/Mechanics/SettingsRow.updatedAt`/`deletedAt`
  → Drift `schemaVersion` 1 → **2** พร้อม `onUpgrade` ที่ `addColumn` ทั้ง 7 คอลัมน์
  (ทุกคอลัมน์ nullable → ข้อมูลเดิมไม่ถูกเขียนทับ)
* `saveSale` เขียน `costAtSale` จาก `products.cost` ในทรานแซกชันเดียวกับที่ตัดสต็อก
* ต่อสาย `updatedAt` ครบ 8 จุดที่แตะ 3 ตารางนั้น (เพิ่ม/แก้ลูกค้า, เพิ่ม/แก้ช่าง,
  รับชำระเครดิต, อัปเดตยอดจากการขาย, การกลับรายการตอนรับคืน, แก้ตั้งค่า)
* `dart analyze` สะอาด · `flutter test` ผ่าน 123 ตัว (เพิ่มเทสต์ใหม่ 2)

### 🎁 ผลพลอยได้ที่ไม่ได้คาดไว้: บิลเก่าอาจไม่ต้องเป็น `NULL` ทั้งหมด

`snapshot_repository` **ทิ้งค่า `it['cost']` จากไฟล์ backup ของแอป JS มาตลอด**
ทั้งที่ JS เก็บต้นทุนไว้บนบรรทัดบิล (คอมเมนต์ใน `products_screen.dart` ระบุเอง:
`i.cost ?? products.find(...).cost ?? 0`)

แก้ให้ import อ่าน `cost` แล้ว และ export ปล่อยกลับออกไปด้วย → **ไฟล์ backup เก่าของร้าน
กู้ต้นทุนย้อนหลังคืนมาได้เท่าที่ JS เคยบันทึกไว้** ไม่ใช่ NULL ทั้งก้อนอย่างที่ ADR นี้สมมติตอนแรก
(ยังเป็น NULL เฉพาะบรรทัดที่ JS เองก็ไม่มีค่า) พร้อมกันนี้ `updatedAt`/`deletedAt` ก็
round-trip ผ่าน export/import แล้ว ไม่งั้น restore ทีเดียวข้อมูล sync หายหมด

---

## เหตุผลที่ไม่ backfill

เติมต้นทุนปัจจุบันลงบิลเก่าทั้งหมด = ได้รายงานที่ดูต่อเนื่องไม่มีช่องว่าง **แต่เป็นการเปลี่ยนตัวเลข
ที่ดูเหมือนจริงลงฐานข้อมูลถาวร** — พอเติมแล้วจะแยกไม่ออกอีกเลยว่าแถวไหนคือของจริง แถวไหนคือของเดา
`NULL` น่าเกลียดกว่าแต่ซื่อสัตย์ และตรวจสอบได้ว่าข้อมูลเริ่มเชื่อถือได้ตั้งแต่วันไหน

## ผลที่ตามมา

* **`01_DATABASE.md`** — เพิ่มคอลัมน์ใน DDL `sale_items` + เพิ่มลง invariant ของ `saveSale` (§7.1)
* **`02_API_SCREENS.md`** — `GET /reports/summary` (กำไรขั้นต้น) ต้องใช้ `cost_at_sale`
  แล้ว fallback ไป `products.cost` เฉพาะแถวที่เป็น `NULL` **พร้อมส่งธงบอกว่ามีแถวประมาณกี่แถว**
* **Drift** — เป็น schema change ต้องรัน `build_runner` (ทำรวดเดียวกับงาน `updatedAt`/`deletedAt`)
* **การรับคืน** (`createReturn`) ควรพา `cost_at_sale` จากบรรทัดเดิมไปด้วย ไม่งั้นกำไรสุทธิหลังคืนจะเพี้ยน

## ✅ แก้แอปที่ร้านใช้อยู่วันนี้แล้ว (2026-09-04)

**หน้า "กำไรเดือนนี้"** (`products_screen.dart`)
* ใช้ `costAtSale` ก่อน → fallback ต้นทุนปัจจุบัน → ถ้าไม่มีเลยนับเป็น *ไม่ทราบ*
* **ตัดหาง `?? 0` ของ JS ทิ้ง** — บรรทัดที่ไม่มีต้นทุนที่ไหนเลยไม่ถูกปัดเป็น 0
  (ซึ่งอ่านออกมาเป็นกำไร 100% และแยกไม่ออกจากของแถมจริง ๆ)
* เพิ่มหมายเหตุใต้ตัวเลข บอกจำนวนรายการที่เป็นค่าประมาณ และจำนวนที่ไม่มีต้นทุน
  — **เดิมหน้าจอไม่บอกอะไรเลย** ทั้งที่ CSV บอกมาตลอด

**CSV `sales-detail`** (`settings_screen.dart`)
* คอมเมนต์ `KNOWN DIVERGENCE` ในไฟล์เขียนไว้เองว่าต้องแก้ยังไง
  (*"add a `cost` RealColumn to SaleItems … but that is a schema change, out of
  scope for this file"*) — ตอนนี้ schema change ทำแล้ว จึงคืน parity กับ JSX ได้
* หัวคอลัมน์เลิกบอก "(ต้นทุนปัจจุบัน)" เพราะไม่จริงอีกต่อไป และ**เพิ่มคอลัมน์ท้ายสุด
  `ที่มาของต้นทุน`** = `ณ วันที่ขาย` / `ต้นทุนปัจจุบัน` / `ไม่มีข้อมูล`
  → ตรวจสอบใน Excel ได้ทีละแถว ไม่ต้องเชื่อทั้งไฟล์แบบเหมารวม
* ต่อท้ายคอลัมน์ ไม่ได้แทรกกลาง — ตำแหน่งคอลัมน์เดิมไม่ขยับ ไฟล์เก่ายังเทียบกันได้

> ⚠️ **ข้อความไทย 3 ชิ้นนี้ผมแต่งเอง** (ไม่มีต้นฉบับใน `db.js` ให้ลอก) — ขัดกับกติกา
> "Thai UI strings = behaviour parity" ในเชิงหลักการ ควรให้เจ้าของร้านอ่านแล้วเลือกคำเอง:
> `'N รายการคำนวณจากต้นทุนปัจจุบัน ไม่ใช่ ณ วันที่ขาย'` ·
> `'N รายการไม่มีข้อมูลต้นทุน (กำไรจะสูงกว่าจริง)'` · หัวคอลัมน์ `'ที่มาของต้นทุน'`

## ✅ ฝั่ง server propagate แล้ว (2026-09-04, scrutinize รอบ 3)
