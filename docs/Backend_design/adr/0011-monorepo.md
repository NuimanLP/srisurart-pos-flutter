# ADR-0011 — `server/` อยู่ใน repo เดียวกับ Flutter client

* **สถานะ:** Accepted — 2026-09-04
* **ผู้ตัดสิน:** เจ้าของโปรเจกต์

## บริบท

`CLAUDE.md` ประกาศไว้ตั้งแต่ 2026-09-04 ว่า *"the server, the client's API layer and the CI/CD
pipelines all land in this repo"* — แต่ประโยคนั้นเขียนตอนที่ยังคิดว่า **มีทีม backend แยก**
พอกลายเป็นว่าคนเขียน client กับคนเขียน server เป็นคนเดียวกัน จึงควรเคาะใหม่โดยตั้งใจ
ไม่ใช่รับมรดกสมมติฐานเก่ามา

repo นี้เคยเป็น Flutter ล้วน การเอา NestJS (`pnpm`, Node 20+) เข้ามาอยู่ด้วยเป็นเรื่องที่
คนอ่านทีหลังจะสงสัยว่าทำไม

## การตัดสินใจ

**`server/` อยู่ที่ root ของ repo นี้ ไม่แยก repo**

เหตุผลหลักคือ **การแก้ API หนึ่งครั้ง = commit เดียว** ที่แตะทั้งสองฝั่ง
สำหรับคนเขียนคนเดียว สิ่งนี้มีค่ามากกว่า CI ที่สะอาด — repo แยกแปลว่าต้องคุมเวอร์ชัน
ระหว่าง client กับ server เอง ซึ่งเป็นงานประจำที่ไม่มีใครทำให้

ผลพลอยได้ที่สำคัญกว่าที่คิด: `lib/data/repositories/` (13 repositories ที่ port มาจาก `pos/db.js`)
**นั่งอยู่ข้าง ๆ** NestJS service ที่ต้องทำกฎเดียวกันซ้ำ — และกฎพวกนั้นคือสิ่งที่มีโอกาส
เพี้ยนออกจากกันมากที่สุด ถ้าอยู่คนละ repo จะไม่มีใครเห็นตอนมันเริ่มต่างกัน

## ผลที่ตามมา

* CI ต้องรองรับสอง toolchain ในไฟล์เดียว — ใช้ `paths:` filter แยก job
  ฝั่ง Flutter ไม่รันเมื่อแตะแค่ `server/` และกลับกัน
* `.gitignore` ต้องคุม `server/node_modules`, `server/dist`
* ⚠️ **ข้อจำกัด path ที่ไม่ใช่ ASCII ใน `CLAUDE.md` ยังมีผลกับทั้ง repo** — ถ้า checkout
  ไปอยู่ใต้ `D:\Beestation\ร้านศรี\` `build_runner` ยังพังเหมือนเดิม และตอนนี้ลาก `server/`
  ไปอยู่ใต้ path นั้นด้วย (Node/pnpm ไม่มีปัญหา แต่ Dart codegen มี)
