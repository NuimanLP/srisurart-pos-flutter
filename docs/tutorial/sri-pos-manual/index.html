ใครอ่านภาคไหน Who reads what

ระบบมี บัญชีร้านเพียงบัญชีเดียว ต่อร้าน (บทบาท owner) — ไม่มีบัญชีแยกของแคชเชียร์หรือผู้จัดการ สิ่งที่ทำได้จึงขึ้นกับ ประเภทเครื่อง ที่ผูกไว้ มากกว่าตัวบุคคล

💳01 พนักงานหน้าร้านใช้เครื่อง POS ขาย คืน ลิ้นชัก ปิดกะ 🏪02 เจ้าของร้านอ่านภาค 01 ด้วย + ผูกเครื่อง สินค้า รายงาน ตรวจรายการ 🛡03 ผู้ดูแลแพลตฟอร์มทีมงานที่เปิดร้านใหม่ ระงับร้าน ออกรหัสผ่านชั่วคราว 🖥04 IT / ผู้ดูแลระบบรันเซิร์ฟเวอร์ deploy สำรองข้อมูล แก้ปัญหา 📈05 แดชบอร์ดIT อ่านสุขภาพระบบจาก Grafana / Prometheus / Bull-Board

ประเภทเครื่อง Device roles (ADR-0004)

ประเภทมีได้กี่เครื่องทำได้ทำไม่ได้
เครื่องขาย (POS)1 เครื่องต่อร้านขาย คืนสินค้า รับชำระเครดิตช่าง เปิด/ปิดกะ บันทึกเงินเข้า-ออกลิ้นชัก พักบิล ออกเลขใบเสร็จ/ใบลดหนี้ ขายต่อได้ตอนเน็ตหลุด—
Backofficeหลายเครื่อง — เลขเครื่อง 1–99 ใช้ร่วมกันทั้งร้าน (นับ POS ด้วย) และเลขของเครื่องที่ปลดแล้วไม่ถูกนำกลับมาใช้สินค้า ลูกค้า ช่าง ซัพพลายเออร์ ใบสั่งซื้อ ปรับสต็อก ใบเสนอราคา ดูรายงานขาย คืน ลิ้นชัก รับชำระเครดิตช่าง — และต้องออนไลน์ตลอด
ยังไม่ผูกเครื่อง—เปิดหน้าเข้าสู่ระบบ และผูกเครื่องได้งานที่ต้องใช้สิทธิ์เครื่อง (เซิร์ฟเวอร์ตอบ เครื่องนี้ขายของไม่ได้)

เส้นแบ่งคือ "แตะลิ้นชักไหม" ไม่ใช่ "แตะสต็อกไหม" — การแบ่งสิทธิ์นี้บังคับที่ เซิร์ฟเวอร์ หน้าจอส่วนใหญ่ไม่ได้ซ่อนปุ่มตามประเภทเครื่อง (ยกเว้นส่วนตั้งค่า PIN ออฟไลน์)

Section 00

ภาพรวมสถาปัตยกรรม Architecture

แอป Flutter (เว็บ/มือถือ) คุยกับเซิร์ฟเวอร์ผ่าน Nginx ตัวเดียว เซิร์ฟเวอร์ NestJS 3 ตัวแชร์ PostgreSQL ที่แยกข้อมูลแต่ละร้านด้วย Row-Level Security (RLS)

เครื่องหน้าร้าน / หลังร้าน เครื่องเซิร์ฟเวอร์ (VM เดียว · 4 vCPU · 6 GB) ┌──────────────────────────┐ ┌────────────────────────────────────────────────┐ │ Flutter app │ HTTPS │ Nginx :443 (TLS · rate limit · เว็บ static) │ │ ├ Drift/SQLite (สำเนา) │ ───────► │ │ least_conn │ │ └ outbox (คิวรอส่ง) │ JWT │ ▼ │ └──────────────────────────┘ │ api-1 api-2 api-3 (NestJS) │ │ │ │ platform-ui :3200 (loopback) ──► Nginx│ ├─► PostgreSQL 16 — ข้อมูลจริง · RLS ต่อร้าน │ │ ├─► redis-cache (ไล่ทิ้งได้) │ │ ├─► redis-queue (ห้ามทิ้ง) ─► worker (BullMQ) │ │ └─► etcd (ค่าตั้งแบบเปลี่ยนสดได้) │ │ Bull-Board :3100 · Prometheus :9090 · Grafana :3000│ │ (เปิดเฉพาะ 127.0.0.1 — เข้าผ่าน SSH tunnel) │ └────────────────────────────────────────────────┘
  • Nginx ต้องเป็น proxy ตัวเดียว หน้า API — ระบบอ่าน IP ลูกค้าจาก X-Forwarded-For ตัวขวาสุด ถ้ามี proxy/CDN ซ้อน ลูกค้าทุกคนจะถูกนับเป็น IP เดียว
  • Redis 2 ตัวโดยตั้งใจ — ตัว cache ไล่ข้อมูลเก่าทิ้งได้ ตัว queue ห้ามทิ้งเด็ดขาด (ถ้ารวมเป็นตัวเดียว งานในคิวอาจหายเงียบ ๆ)
  • worker ทำงานเบื้องหลัง 5 คิว (หลังขาย ตรวจสต็อก บำรุงรักษา ส่งออกข้อมูล นำเข้าข้อมูล) — งานที่ล้มครบ 3 ครั้งไปพักในคิว dlq ซึ่งไม่มี worker — ดูภาค 05
  • etcd เก็บเฉพาะค่าตั้งที่ไม่ลับ (วันนี้มีคีย์เดียว /pos/config/log_level) ไม่ใช่ข้อมูลธุรกิจ

ระยะที่ 1 กับระยะที่ 2 Phase 1 vs 2

ระยะคืออะไรสถานะ
Phase 1เซิร์ฟเวอร์ + RLS + transaction/idempotency + ชั้นเขียนผ่าน API ของแอป (ข้อมูลจริงอยู่บนเซิร์ฟเวอร์ เครื่องเป็นแค่สำเนา)โค้ดรวมเข้า main แล้ว — เกณฑ์เสร็จ 16 จาก 17 ข้อ (ค้างข้อทดสอบโหลด k6)
Phase 2ขายต่อได้ตอนเน็ตหลุด: outbox คิวรอส่ง, เครื่อง POS เครื่องเดียวต่อร้าน, PIN ออฟไลน์, ออกเลข RC/CN ได้ทั้งออนไลน์และออฟไลน์, หน้า "รอเจ้าของ"กำลังทำ — ตั๋วหลักเหลือ #231 (การย้ายร้านจริง / cutover)
ร้านจริงวันนี้ร้านยังใช้ Drift build บนเครื่องหน้าร้าน ข้อมูลอยู่ในเครื่องนั้นเครื่องเดียว — เซิร์ฟเวอร์ข้างบนมีอยู่จริง รันและทดสอบได้ แต่ ยังไม่มีร้านจริงเชื่อมต่อ และ ยังไม่เคย deploy ขึ้น VM ของคณะ (mob04) สำเร็จ

สถานะจริงวันนี้ Honest status · 2026-09-27

รายการนี้มีไว้กันการเข้าใจผิด — ถ้าคู่มือส่วนใดขัดกับกล่องนี้ ให้เชื่อกล่องนี้ และเช็กสถานะล่าสุดใน README.md (Known bottlenecks / Roadmap) และ GitHub issues

ข้อจำกัดปัจจุบัน Current limitations
  • ยังไม่ cutover — ร้านใช้ Drift build แบบออฟไลน์ ไม่มีการเข้าสู่ระบบ ไม่มีการผูกเครื่อง
  • CD ขึ้น mob04 ยังไม่เคยสำเร็จ — firewall ของมหาวิทยาลัยตรวจ SSL แล้วตอบ ghcr.io ด้วยใบรับรองที่ไม่มี SAN ทำให้ docker compose pull ล้ม และยังไม่มี self-hosted runner ลงทะเบียนเลย (0 ตัว) — การ Deploy (demo) ที่ขึ้นเขียวใน GitHub ไม่ได้แปลว่าขึ้นเครื่องแล้ว
  • ยังไม่มี backup ออกนอก VM — งาน offsite ถูกพักไว้จนหลังเดโม ถ้าดิสก์ mob04 เสีย ข้อมูลร้าน demo หายหมด
  • etcd บน mob04 ยังไม่เปิดระบบรหัสผ่าน (#365) และ CORS_ORIGINS บน VM ยังเป็น '*'
  • ยังไม่ได้วัดโหลด (#380) — แผง k6 ใน Grafana จึงว่าง
  • platform-ui (#443) รวมโค้ดแล้วแต่ยังไม่ deploy การทดสอบ 403 สองชั้นวัดบน Docker Desktop เท่านั้น ยังไม่ได้วัดบน Linux/mob04
  • หน้า ลิ้นชัก: ระบบรองรับหลายกะต่อวัน แต่หน้าจอยังไม่มีปุ่มเปิดกะใหม่หลังปิดลิ้นชักไปแล้วในวันเดียวกัน (ดูภาค 01)
  • คืนสินค้าตอนออฟไลน์: หน้าคืนสินค้าใน API build ยังส่งไปเซิร์ฟเวอร์โดยตรง ไม่ได้เข้าคิวรอส่ง — ต้องมีเน็ต (ดูภาค 01)
  • ฮาร์ดแวร์หน้าร้าน (เครื่องพิมพ์ความร้อนสั่งตรง ลิ้นชักเด้ง สแกนบาร์โค้ดด้วยกล้อง) ยังไม่ทำ — การพิมพ์ใช้หน้าต่างพิมพ์ของระบบปฏิบัติการ
