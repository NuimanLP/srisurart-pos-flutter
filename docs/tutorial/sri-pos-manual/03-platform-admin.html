ผู้ดูแลแพลตฟอร์ม Platform admin

ทีมงานที่ดูแล "ทุกร้าน" บนระบบเดียว — สร้างผู้ดูแลคนแรก เปิดร้านใหม่ ส่งรหัสให้เจ้าของร้าน ระงับ/เปิดร้าน ออกรหัสผูกเครื่องใหม่ และออกรหัสผ่านชั่วคราวเมื่อเจ้าของร้านลืม

บทบาทและสิทธิ์ · Role & permission
ใครใช้
ทีมงาน (ไม่ใช่คนของร้าน) — บัญชีอยู่ในตาราง platform_admins แยกจากบัญชีร้านโดยสิ้นเชิง (ADR-0002)
ต้องมี
สิทธิ์เข้าเครื่องเซิร์ฟเวอร์ (หรือ SSH tunnel) — หน้า platform-ui เปิดได้เฉพาะ 127.0.0.1:3200
ทำได้
สร้างร้าน · ดูรายชื่อ/รายละเอียดร้าน · เปลี่ยนสถานะ active/suspended/closed · ออกรหัสผูกเครื่องใหม่ (เครื่องที่ยังไม่เคยผูก) · ออกรหัสผ่านชั่วคราวให้เจ้าของร้าน · ดูงานนำเข้าข้อมูล
ทำไม่ได้
สร้างผู้ดูแลแพลตฟอร์มผ่านเว็บหรือ API (ต้องใช้คำสั่งบนเซิร์ฟเวอร์เท่านั้น — ADR-0001) · ตั้งรหัสผ่านเจ้าของร้านเอง (เซิร์ฟเวอร์สุ่มให้) · เห็นข้อมูลขายของร้าน

สร้างผู้ดูแลคนแรก bootstrap-admin

ทำครั้งเดียวต่อฐานข้อมูล บนเครื่องที่รันสแตกอยู่ (ดูวิธีรันในภาค 04) — ไม่มีปุ่มหรือ API ให้ทำเรื่องนี้

  1. เข้าโฟลเดอร์ server/ ของเครื่องที่รันสแตก
  2. รันคำสั่งในคอนเทนเนอร์ api-1รหัสผ่านอย่างน้อย 12 ตัวอักษร 
    docker compose -f docker-compose.yml -f docker-compose.dev.yml -f ../deploy/compose/monitoring.yml exec -T \
  -e BOOTSTRAP_ADMIN_USERNAME=<admin> \
  -e BOOTSTRAP_ADMIN_PASSWORD=<รหัสผ่านอย่างน้อย12ตัวอักษร> \
  -e BOOTSTRAP_ADMIN_DISPLAY_NAME="<ชื่อที่แสดง>" \
  api-1 sh -c 'DATABASE_URL="postgres://postgres:$POSTGRES_PASSWORD@postgres:5432/pos" node dist/db/bootstrap-admin.js'
    ข้อความ created
  3. ถ้าขึ้น already exists — password left aloneบัญชีนี้มีอยู่แล้ว และ รหัสใหม่ไม่ได้ถูกบันทึก — รันคำสั่งเดิมโดยเติม --force ท้าย bootstrap-admin.js แล้วต้องเห็น password reset (ข้อความเต็มตอนแรกคือ already exists — password left alone (pass --force to reset it))
  4. ทดสอบเข้าสู่ระบบที่ platform-ui (หัวข้อ 2) หรือ CLI login (หัวข้อ 4)
อย่าใส่รหัสผ่านใน historyคำสั่งนี้ส่งรหัสทางตัวแปรแวดล้อม — บนเครื่องที่ใช้ร่วมกัน ให้ล้าง shell history หลังใช้ หรือใช้ --force เปลี่ยนรหัสทันทีหลังทดสอบ
dev กับ VM จริงตัวอย่างข้างบนคือชุด -f ของเครื่อง dev (local-full-stack-tutorial.md ข้อ 5.1) — บน mob04 อิมเมจจริงไม่มี pnpm จึงต้องเรียก node dist/… แบบเดียวกันนี้ และ ยังไม่เคยทำบน mob04 เพราะยังไม่เคย deploy สำเร็จ

Section 2

platform-ui: สร้างร้าน · ส่งมอบรหัส Create tenant

หน้าเว็บ Srisurart POS — แผงควบคุมแพลตฟอร์ม (Platform Admin) ที่ http://127.0.0.1:3200 — บน VM ให้เปิด tunnel ก่อน: ssh -L 3200:127.0.0.1:3200 deploy@<vm> แล้วเปิด URL เดียวกัน

  1. กรอก ชื่อผู้ใช้ (Username) / รหัสผ่าน (Password) → เข้าสู่ระบบการ์ด สร้างร้านใหม่ (Create tenant) และ รายชื่อร้านทั้งหมด (Tenants) — session อยู่ 1 ชั่วโมง ปิดแท็บ = ต้องเข้าใหม่
  2. กรอกฟอร์มสร้างร้านรหัสร้าน (code) · ชื่อร้าน (shopName) · ชื่อร้าน (อังกฤษ, ถ้ามี) · ชื่อผู้ใช้เจ้าของร้าน (ownerUsername) · ชื่อที่แสดงของเจ้าของร้าน (ownerDisplayName) — ระบบจะสร้างรหัสผ่านชั่วคราวให้เจ้าของร้านเอง — ไม่มีช่องให้ตั้งรหัสผ่านที่นี่
  3. กด สร้างร้านหน้าต่าง สร้างร้าน "{shopName}" สำเร็จ พร้อมคำเตือน ข้อมูลนี้จะแสดงครั้งเดียวเท่านั้น — คัดลอกและส่งให้ร้านทันที
  4. กด คัดลอก (Copy) ทั้ง 2 รายการรหัสผ่านชั่วคราวของเจ้าของร้าน ({ownerUsername}) — อายุ 7 วัน เจ้าของร้านต้องเปลี่ยนตอนเข้าครั้งแรก · รหัสลงทะเบียนอุปกรณ์ (enrolCode) — ใช้ได้ 7 วัน สำหรับเครื่องขายเครื่องแรก (pos1)
  5. กด ปิด (Close) แล้วส่งมอบให้เจ้าของร้านแบบตัวต่อตัวส่งชื่อผู้ใช้ + รหัสผ่านชั่วคราว + รหัสผูกเครื่อง แล้วชี้ไปที่ภาค 02 หัวข้อ 1

การสร้างร้านทำในธุรกรรมเดียว: ร้าน + บัญชีเจ้าของ + ค่าตั้งเริ่มต้น + หมวดสินค้า 5 หมวด + เครื่อง pos1 · รหัสร้านหรือชื่อผู้ใช้ซ้ำจะได้ 409 … already exists — ใช้ค่าใหม่

Section 3

รายละเอียดร้าน Tenant detail

ในตารางรายชื่อร้าน กด โหลดใหม่ (Refresh) เพื่ออัปเดต แล้วกด ดูรายละเอียด (detail) ที่แถวร้าน — หัวร้านแสดง แผน: … · เขตเวลา: … · สถานะปัจจุบัน: … · สร้างเมื่อ: …

เปลี่ยนสถานะร้าน Status

  • เปิดใช้งาน (activate) → ยืนยันเปิดใช้งานร้านนี้หรือไม่?
  • ระงับชั่วคราว (suspend) → ยืนยันระงับการใช้งานร้านนี้ชั่วคราวหรือไม่? — ร้านจะเห็น ร้านนี้ถูกระงับการใช้งาน
  • ปิดร้านถาวร (close) → ยืนยันปิดร้านนี้ถาวรหรือไม่? การกระทำนี้ควรทำเมื่อแน่ใจแล้วเท่านั้น

อุปกรณ์ · ออกรหัสผูกเครื่องใหม่ Devices

ตาราง อุปกรณ์ (Devices) แสดงสถานะ ผูกเครื่องแล้ว (enrolled) / ยังไม่ผูกเครื่อง (not enrolled) / ยังไม่ผูกเครื่อง — รหัสหมดอายุ (code expired) / ยกเลิกแล้ว (retired)

  1. ใช้เมื่อร้านทำรหัสผูกเครื่องแรกหาย ก่อนเคยผูกเครื่องใดเลยปุ่มมีเฉพาะเครื่องที่ ยังไม่เคยผูก
  2. กด ออกรหัสใหม่ (reissue code)รหัสลงทะเบียนใหม่สำหรับอุปกรณ์ {deviceId} — แสดงครั้งเดียว มีอายุ 7 วัน

เครื่องที่ผูกแล้วและต้องเปลี่ยน — เจ้าของร้านปลดเครื่องและออกรหัสใหม่เองจากแอป (ภาค 02 หัวข้อ 2)

รหัสผ่านเจ้าของร้าน (ลืมรหัส) Owner temp password

  1. โทรกลับไปที่เบอร์/อีเมลที่ร้านให้ไว้ตอนเปิดร้านห้ามเชื่อเบอร์ที่ผู้โทรเข้ามาแจ้งเอง
  2. กด ออกรหัสผ่านชั่วคราวใหม่ (reset) → ยืนยันว่าโทรกลับแล้วรหัสเดิมของเจ้าของร้านใช้ไม่ได้ทันที
  3. คัดลอกรหัสจากหน้าต่างหมดอายุใน 24 ชม.: … — เจ้าของร้านต้องเปลี่ยนรหัสตอนล็อกอินครั้งถัดไป

การ์ด งานนำเข้าข้อมูลล่าสุด (Recent import jobs) แสดงงานนำเข้า 20 รายการล่าสุด พร้อมสถานะและข้อผิดพลาด (ดูรายละเอียดงานเสียใน Bull-Board ภาค 05)

Section 4

Platform CLI server/src/cli/platform.ts

ทำได้ทุกอย่างเหมือน platform-ui รันจาก ภายในคอนเทนเนอร์ api-1 ยิงตรงเข้า API พอร์ต 3000 (ไม่ผ่าน Nginx จึงไม่ติด allowlist) — รหัสผ่านพิมพ์ตอนถูกถามเท่านั้น ไม่มี flag --password และไม่เก็บ token

docker compose exec api-1 node dist/cli/platform.js <คำสั่ง> --user <admin> …
# Platform admin password: <พิมพ์>
คำสั่งใช้ทำอะไร
login --user <admin>ทดสอบเข้าสู่ระบบ (ไม่จำเป็นก่อนคำสั่งอื่น)
tenants:create --user <admin> --code <c> --shop-name <n> [--shop-name-en] [--plan basic|demo|loadtest] [--timezone] --owner-username <u> [--owner-display-name]สร้างร้าน — ได้ tenantId, tempPassword, enrolCode (แสดงครั้งเดียว อายุ 7 วัน) · ค่าเริ่มต้น --plan basic, --timezone Asia/Bangkok
tenants:list --user <admin>รายชื่อร้าน (JSON)
tenants:show <tenantId> --user <admin>ร้าน + รายการเครื่อง + งานนำเข้า 20 รายการล่าสุด
tenants:status <tenantId> <active|suspended|closed> --user <admin>เปลี่ยนสถานะร้าน
devices:reissue-code <tenantId> <deviceId> --user <admin>ออกรหัสผูกเครื่องใหม่ (เครื่องที่ยังไม่เคยผูก) อายุ 7 วัน
owner:temp-password <tenantId> --user <admin>ออกรหัสผ่านชั่วคราวใหม่ อายุ 24 ชม. — โทรกลับยืนยันตัวตนก่อน
owner:set-password <username>เข้าด้วยรหัสชั่วคราวแล้วตั้งรหัสจริงในคำสั่งเดียว — ใช้กับร้าน demo/loadtest ของทีมเท่านั้น ห้ามใช้กับร้านจริง
PowerShellการ pipe รหัสผ่านจาก PowerShell เข้า stdin ได้รหัสที่เพี้ยน (encoding/บรรทัดท้าย) → เข้าไม่ได้ทั้งที่รหัสถูก ให้พิมพ์แบบ interactive (ไม่ใส่ -T) หรือใช้ Git Bash: 
printf '%s\n' '<รหัส admin>' | docker compose exec -T api-1 node dist/cli/platform.js login --user <admin>

ส่ง ownerPassword ไปที่ API ตรง ๆ จะถูกปฏิเสธ 400 OWNER_PASSWORD_NOT_ACCEPTED ก่อนสร้างอะไร (ข้อความตอบกลับเป็นภาษาอังกฤษ) · รายละเอียดเพิ่ม: docs/handoff_log/ticket-338-platform-provision.md §3

Section 5

แก้ปัญหา 403 · allowlist Troubleshooting

/api/v1/platform/ ถูกกันสองชั้น: Nginx (allow) และ guard ของ API (PLATFORM_ADMIN_IPS) — platform-ui ผ่านได้เพราะคอนเทนเนอร์มี IP ตายตัว 172.30.0.20 และเรียก API ผ่าน Nginx หลักเสมอ

อาการสาเหตุแก้
เรียก /api/v1/platform/… จากโฮสต์ หรือผ่าน ssh -L เข้า Nginx ตรง ๆ ได้ 403docker-proxy เปิด connection ใหม่ IP ต้นทางกลายเป็น gateway 172.30.0.1 — เกิดทุกโฮสต์ รวม mob04ใช้ platform-ui :3200 หรือ CLI จากในคอนเทนเนอร์ api-1
เปิด :3200 ได้ แต่เข้าสู่ระบบ/โหลดรายชื่อร้านได้ 403PLATFORM_ADMIN_IPS ถูกตั้งทับโดยไม่มี 172.30.0.20 หรือ network ถูกสร้างใหม่จนเสีย IP ตายตัวลบค่าที่ตั้งทับ หรือเพิ่ม 172.30.0.20 แล้ว up -d · ตรวจ IP ด้วย docker inspect
เรียก API :3000 ตรงพร้อม XFF นอก allowlist ได้ 403 PLATFORM_IP_FORBIDDENguard ของ API ทำงานตามปกติไม่ต้องแก้ — ใช้ช่องทางที่ถูก
เซสชันหมดอายุ กรุณาเข้าสู่ระบบใหม่ (session expired)token 1 ชม. ไม่มี refreshเข้าสู่ระบบใหม่
เชื่อมต่อเซิร์ฟเวอร์ไม่ได้ (network error)สแตก/Nginx ไม่ทำงานตรวจตามภาค 04 หัวข้อ health check
3 ค่าที่ต้องเปลี่ยนพร้อมกันถ้าจะเปลี่ยน IP ของ platform-ui ต้องแก้ครบ 3 ที่ ไม่เช่นนั้นจะได้ 403 แบบเงียบ ๆ:
  • ipv4_address: 172.30.0.20 ใน server/docker-compose.yml
  • allow 172.30.0.20; ใน server/docker/nginx/nginx.conf (location /api/v1/platform/)
  • PLATFORM_ADMIN_IPS (ค่าเริ่มต้นใน compose คือ 172.30.0.20)
ข้อจำกัดปัจจุบัน Current limitations
  • platform-ui และ CLI (#443) รวมโค้ดแล้ว แต่ ยังไม่ได้ deploy — ใช้ได้เฉพาะสแตก dev/ทดสอบ
  • ผลวัด 403 สองชั้นวัดบน Docker Desktop เท่านั้น ยังไม่ได้วัดบน Linux/mob04 จริง
  • ตั๋ว #443 ยังเปิดอยู่ รอคำตอบจากเจ้าของโปรเจกต์บางข้อ (docs/handoff_log/session-2026-09-27-platform-admin-ui-443.md §6)
  • ยังไม่มีร้านจริงบนแพลตฟอร์ม — ร้านจริงยังใช้ Drift build
