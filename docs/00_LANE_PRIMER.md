## 🐣 ภาค 1: ปูพื้นฐาน — เรากำลังสร้างอะไรกันอยู่วะ?

จินตนาการว่าเดิมที **ร้านศรีสุราษฎร์อะไหล่ยนต์** มีโปรแกรมขายหน้าร้าน (POS) ตัวนึงรันอยู่ในคอมพิวเตอร์เครื่องเก่าที่ตั้งอยู่บนเคาน์เตอร์  
- ข้อมูลทุกอย่าง เช่น สินค้า, หนี้ช่าง, สต็อกลูกสูบ, ยอดขาย **ถูกฝังอยู่ในคอมเครื่องนั้นเครื่องเดียว**  
- วันดีคืนดี ถ้าไฟดับ, คอมพัง, หรือหนูกัดสายไฟ = **ข้อมูลหายหมด ร้านเจ๊งทันที**  
- แถมเปิดสาขา 2 ไม่ได้, เจ้าของร้านนั่งดูกำไรจากบ้านผ่านมือถือไม่ได้

พวกเราก็เลยได้รับภารกิจ: **"ยกเครื่องใหม่หมดจด ให้กลายเป็นระบบคลาวด์สุดเทพ (Multi-tenant Cloud System)"**

---

### 🧩 องค์ประกอบของระบบมี 4 ส่วนหลัก (คิดเหมือนเปิดร้านอาหาร)

```
┌─────────────────────────────────────────────────────────────┐
│ 1. หน้าร้าน (Frontend - Flutter)                             │
│    เปรียบเหมือน: "หน้าจอ iPad เมนูอาหารสวยๆ ที่พนักงานแคชเชียร์จิ้ม"│
└──────────────────────────────┬──────────────────────────────┘
                               │ กดสั่งอาหาร / คิดเงิน (HTTP Request)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. ผู้จัดการร้าน (Backend - NestJS)                           │
│    เปรียบเหมือน: "ผู้จัดการร้านคอยเช็คกฎ: ขอยืมของได้ไหม?       │
│    เงินทอนพอไหม? คนสั่งมีสิทธิ์สั่งไหม? หักสต็อกแล้วส่งต่อ"       │
└──────────────┬──────────────────────────────┬───────────────┘
               │ บันทึกข้อมูล                  │ ฝากจำของถามบ่อย
               ▼                              ▼
┌──────────────────────────────┐ ┌────────────────────────────┐
│ 3. สมุดบัญชีหลัก             │ │ 4. กระดานไวท์บอร์ดด่วน      │
│    (Database - PostgreSQL)   │ │    (Cache & Queue - Redis) │
│    เปรียบเหมือน:              │ │    เปรียบเหมือน:           │
│    "ตู้เซฟทองคำเก็บสมุดบัญชี    │ │    "ไวท์บอร์ดแปะเมนูขายดี  │
│    จดทุกบาททุกสตางค์ ห้ามหาย!" │ │    + ตะกร้าส่งงานให้คนงาน"  │
└──────────────────────────────┘ └────────────────────────────┘
                               ▲
                               │ คอยตรวจสอบ
┌──────────────────────────────┴──────────────────────────────┐
│ 5. ครูฝ่ายปกครอง / รปภ. (CI/CD - GitHub Actions)              │
│    เปรียบเหมือน: "สารวัตรนักเรียน คอยตรวจการบ้านก่อนปล่อยเข้าเซิร์ฟ" │
└─────────────────────────────────────────────────────────────┘
```

1. **Frontend (Flutter):** หน้าจอ UI สวยงาม มีปุ่มกดคิดเงิน, ค้นหายี่ห้อรถ, ออกใบเสร็จ รันได้ทั้งมือถือ, แท็บเล็ต และเว็บ
2. **Backend (NestJS):** สมองกลส่วนกลาง ทำหน้าที่รับคำสั่งจาก Frontend ตรวจสอบความถูกต้องและคิดเลข
3. **Database (PostgreSQL):** โกดังข้อมูลเก็บ 27 ตาราง (สต็อก, บิล, ลูกค้า, เงิน)
4. **Redis & BullMQ:** โต๊ะวางของด่วน ช่วยให้ระบบทำงานเร็วปานสายฟ้าแลบ และสายพานส่งงานเบื้องหลัง
5. **Multi-Tenant (มัลติเทแนนต์):** แปลง่ายๆ คือ **"ระบบหอพัก"** — เซิร์ฟเวอร์มีชุดเดียว แต่ให้ร้านค้าเช่าได้ 100 ร้าน โดยร้าน A ไม่มีทางแอบเปิดดูข้อมูลของร้าน B เด็ดขาด!

## 🚦 ภาค 2: ทำไมต้องแตกงานเป็น 42 Tickets? แล้วทำไมต้องแบ่งเป็น 3 Lane?

ถ้าปล่อยให้พวกเรา 3 คนเดินเข้าไปแล้วบอกว่า *"เฮ้ย มารุมเขียนโค้ดร้านค้ากันเถอะ"* สิ่งที่จะเกิดขึ้นคือ:
- ทุกคนแย่งกันแก้ไฟล์เดียวกัน
- พอจะกดรวมโค้ด (Merge) โค้ดชนกันระเบิดเป็นโกโก้ครั้นช์ (Merge Conflict)
- ไม่มีใครรู้ว่างานไหนต้องทำก่อน-หลัง

อาจารย์ก็เลยตั้งกฎเหล็กขึ้นมาว่า:  
👉 **"ทุกคนในทีม 3 คน ต้องได้แตะครบทั้ง 3 สาย: Frontend + Backend + CI/CD"**

งานประมาณ 42 ตัวจึงถูกจัดกลุ่มเป็น **3 เลน (3 ทีม)** ทำงานคู่ขนานกันเหมือนกองทัพ 3 เหล่า:

```
[Team 1 / Lane A]  💰 แก๊งการเงิน & แคชเชียร์      (NuimanLP)
[Team 2 / Lane B]  📦 แก๊งคลังสินค้า ทะเบียน & รายงาน (LomerAlloys)
[Team 3 / Lane C]  🛡️ แก๊ง รปภ. คุมประตู & ช่างเทคนิค (PattaraponKitcharoen)
```

## 📖 ภาค 6: พจนานุกรมศัพท์เทคนิค (Tech Glossary) — แปลงร่างศัพท์หรูเป็นภาษาคน

เวลานั่งคุยงานหรืออ่านโค้ดแล้วเจอศัพท์ฝรั่งเท่ๆ แต่ฟังแล้วมึนหัว เปิดหน้านี้มาดูได้เลย:

| คำศัพท์ (Technical Term) | คำแปลภาษาคน | ตัวอย่างในร้าน POS เรา |
|---|---|---|
| **RLS (Row Level Security)** | **ยามเฝ้าตู้เซฟระดับแถว** | ใน Database มีตารางบิลรวมกันทุกร้าน แต่ RLS จะแอบตรวจอัตโนมัติว่า "มึงร้านไหน?" แล้วส่งมาให้ดูเฉพาะบิลร้านตัวเอง ร้านอื่นหมดสิทธิ์เสือก |
| **Idempotency** | **บัตรคิวกันกดเบิ้ล (ทำกี่ครั้งผลเท่าเดิม)** | ลูกค้าจ่ายเงินแล้วเน็ตหลุด มือสั่นกดปุ่มคิดเงินย้ำ 5 รอบ ระบบจะไม่ตัดเงิน 5 ครั้ง แต่ตอบใบเสร็จเดิมกลับมา |
| **Critical Path (เส้นทางวิกฤต)** | **โดมิโนตัวพ่อ ห้ามล้มห้ามอู้** | งานชิ้นที่ถ้ายังไม่เสร็จ งานของคนอื่นจะเริ่มไม่ได้เลย เช่น ต้องสตาร์ท Docker (#14) กับสร้างตาราง DB (#15) ก่อน ถึงจะเริ่มเขียนระบบคิดเงิน (#20) ได้ |
| **JWT (JSON Web Token)** | **สายรัดข้อมือ VIP เข้างาน** | พนักงานล็อกอินใส่รหัสผ่านครั้งเดียว จะได้ Token มารัดข้อมือไว้ ยิงคำขอต่อไปแค่ชูสายรัดข้อมือ ไม่ต้องกรอกรหัสใหม่ทุกหน้าจอ |
| **Device Roles / Scopes** | **ยศและหน้าที่ประจำเครื่อง** | เครื่อง POS หน้าร้านมีสิทธิ์คิดเงิน/ตัดสต็อก แต่คอมเครื่องหลังบ้านให้เปิดดูรายงานได้อย่างเดียว ห้ามแอบกดคิดเงิน |
| **Schema & Migrations** | **พิมพ์เขียว & ประวัติการต่อเติมตึก** | *Schema* คือโครงสร้างตารางว่ามีฟิลด์อะไรบ้าง ส่วน *Migrations* คือสคริปต์จดบันทึกเวอร์ชันของการแก้ DB เพื่อให้เครื่องทุกคนในทีมมีหน้าตาฐานข้อมูลตรงกันเป๊ะ |
| **Cache (Redis)** | **กระดานไวท์บอร์ดหน้าครัว** | สินค้าไหนคนค้นหาหรือถามราคาบ่อยๆ จดแปะไว้บนบอร์ดความเร็วสูง (RAM) ไม่ต้องเดินไปเปิดตู้เซฟ Database ให้เสียเวลาและเปลืองแรง |
| **Queue & Worker (BullMQ)** | **ตะกร้าฝากงานหนักหลังร้าน** | งานหนักๆ ที่ใช้เวลาทำนาน (เช่น ย้ายข้อมูลสต็อกล้านชิ้น, ออกรายงานสิ้นเดือน) จะถูกหย่อนลงตะกร้า แล้วให้คนงานหลังร้านค่อยๆ ทำ หน้าจอแคชเชียร์จะได้ไม่ค้าง |
| **Rate Limiting** | **ประตูกั้นกันคนแห่เหยียบกันตาย** | จำกัดว่าใน 1 นาที เครื่องหรือคนหนึ่งจะยิงเข้ามาได้กี่ครั้ง ถ้ากดยิงรัวเป็นปืนกล ระบบจะดีดออกทันทีเพื่อไม่ให้เซิร์ฟเวอร์สำลักล่ม |
| **Load Testing (k6)** | **ปล่อยฝูงซอมบี้ถล่มเซิร์ฟเวอร์** | เอาโปรแกรมจำลองคนซื้อของ 200–500 คนพร้อมกัน เพื่อดูว่าระบบจะพังไหม สต็อกติดลบหรือเปล่า ก่อนเอาไปใช้จริง |
| **CI/CD Pipeline** | **ครูฝ่ายปกครองตรวจการบ้านอัตโนมัติ** | ทุกครั้งที่ Push โค้ดขึ้น GitHub จะมีหุ่นยนต์มารันเทสต์ เช็คไวยากรณ์ สร้างระบบจำลอง ถ้าโค้ดพังจะตีมือไม่ให้รวมเข้า Main |
| **Docker / Container** | **กล่องพัสดุหิ้วสภาพแวดล้อมข้ามโลก** | แพ็กโปรแกรมและเครื่องมือที่ต้องใช้ใส่กล่องเดียว รันบนเครื่องใครก็ได้ผลเหมือนกันเป๊ะ เลิกเถียงกันว่า *"เครื่องกูรันได้ แต่ทำไมเครื่องมึงรันไม่ได้"* |
| **Multi-tenant** | **คอนโด 1 หลังแบ่งห้องให้เช่า** | เซิร์ฟเวอร์และฐานข้อมูลตัวเดียว แต่รองรับได้หลายสาขา/หลายร้านค้า โดยที่ข้อมูลของแต่ละร้านแยกขาดจากกันเด็ดขาด |
| **RS256 vs HS256** 🆕 | **ตราประทับกุญแจคู่ vs กุญแจลับใบเดียว** | *HS256* = ทุกคนที่ต้อง**ตรวจ**บัตร ถือกุญแจที่**ปลอมบัตร**ได้ด้วย กุญแจหลุดจากเครื่องไหนก็ปลอมเป็นใครก็ได้ทุกร้าน · *RS256* = คนออกบัตรถือ "ตราปั๊ม" ไว้คนเดียว คนอื่นถือแค่ "แว่นส่องว่าตราจริงไหม" · **เราเลือก RS256** (ADR-0009) |
| **Audit Log** 🆕 | **สมุดบันทึกเวรยาม / กล้องวงจรปิด** | จดทุกครั้งที่มีคนทำสิ่งที่ย้อนกลับยาก เช่น ยกเลิกบิล ปรับสต็อก ย้ายเครื่องขาย · เครื่องหน้าร้านเป็นเครื่องกลาง ใครเดินมาก็กดได้ **ถ้าไม่จด เวลาเงินไม่ตรงจะสืบไม่ได้ว่าใครทำ** (#43) |
| **CVE / Dependency Scan** 🆕 | **ตรวจว่าของที่หยิบมาใช้มีไวรัสไหม** | โปรแกรมเราหยิบโค้ดคนอื่นมาใช้เป็นร้อยชิ้น บางชิ้นถูกประกาศทีหลังว่ามีช่องโหว่ · หุ่นยนต์ใน CI เช็คให้ทุกครั้งที่ push เจอของอันตรายคือ **build แดง** (เจอจริง 3 ตัววันแรกที่ติดตั้ง) |
| **OWASP Top 10** 🆕 | **เช็กลิสต์ 10 ท่าไม้ตายที่โจรชอบใช้** | รายการช่องโหว่ยอดฮิตที่วงการยอมรับเป็นมาตรฐาน เอาไว้ไล่เช็กว่าระบบเราปิดครบหรือยัง · ตารางว่าเราปิดข้อไหนด้วยอะไร อยู่ใน `04_QA_SCRUTINY.md` รอบ 4 (#44) |
