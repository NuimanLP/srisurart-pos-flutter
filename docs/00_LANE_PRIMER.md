## 🐣 ภาค 1: ปูพื้นฐาน — เรากำลังสร้างอะไรกันอยู่วะ?

จินตนาการว่าเดิมที **ร้านศรีสุราษฎร์อะไหล่ยนต์** มีโปรแกรมขายหน้าร้าน (POS) ตัวนึงรันอยู่ในคอมพิวเตอร์เครื่องเก่าที่ตั้งอยู่บนเคาน์เตอร์  
- ข้อมูลทุกอย่าง เช่น สินค้า, หนี้ช่าง, สต็อกลูกสูบ, ยอดขาย **ถูกฝังอยู่ในคอมเครื่องนั้นเครื่องเดียว**  
- วันดีคืนดี ถ้าไฟดับ, คอมพัง, หรือหนูกัดสายไฟ = **ข้อมูลหายหมด ร้านเจ๊งทันที**  
- แถมเปิดสาขา 2 ไม่ได้, เจ้าของร้านนั่งดูกำไรจากบ้านผ่านมือถือไม่ได้

พวกเราก็เลยได้รับภารกิจ: **"ยกเครื่องใหม่หมดจด ให้กลายเป็นระบบคลาวด์สุดเทพ (Multi-tenant Cloud System)"**

### 🧩 องค์ประกอบของระบบมี 4 ส่วนหลัก (คิดเหมือนเปิดร้านอาหาร)

```
┌─────────────────────────────────────────────────────────────┐
│ 1. หน้าร้าน (Frontend - Flutter)                             │
│    เปรียบเหมือน: "หน้าจอ iPad เมนูอาหารสวยๆ ที่พนักงานแคชเชียร์จิ้ม"│
└──────────────────────────────┬──────────────────────────────┘
                               │ กดสั่งอาหาร / คิดเงิน (HTTP Request)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. ผู้จัดการร้าน (Backend - NestJS)                           │
│    เปรียบเหมือน: "ผู้จัดการร้านคอยเช็คกฎ: ขอยืมของได้ไหม?       │
│    เงินทอนพอไหม? คนสั่งมีสิทธิ์สั่งไหม? หักสต็อกแล้วส่งต่อ"       │
└──────────────┬──────────────────────────────┬───────────────┘
               │ บันทึกข้อมูล                  │ ฝากจำของถามบ่อย
               ▼                              ▼
┌──────────────────────────────┐ ┌────────────────────────────┐
│ 3. สมุดบัญชีหลัก             │ │ 4. กระดานไวท์บอร์ดด่วน      │
│    (Database - PostgreSQL)   │ │    (Cache & Queue - Redis) │
│    เปรียบเหมือน:              │ │    เปรียบเหมือน:           │
│    "ตู้เซฟทองคำเก็บสมุดบัญชี    │ │    "ไวท์บอร์ดแปะเมนูขายดี  │
│    จดทุกบาททุกสตางค์ ห้ามหาย!" │ │    + ตะกร้าส่งงานให้คนงาน"  │
└──────────────────────────────┘ └────────────────────────────┘
                               ▲
                               │ คอยตรวจสอบ
┌──────────────────────────────┴──────────────────────────────┐
│ 5. ครูฝ่ายปกครอง / รปภ. (CI/CD - GitHub Actions)              │
│    เปรียบเหมือน: "สารวัตรนักเรียน คอยตรวจการบ้านก่อนปล่อยเข้าเซิร์ฟ" │
└─────────────────────────────────────────────────────────────┘
```

1. **Frontend (Flutter):** หน้าจอ UI สวยงาม มีปุ่มกดคิดเงิน, ค้นหายี่ห้อรถ, ออกใบเสร็จ รันได้ทั้งมือถือ, แท็บเล็ต และเว็บ
2. **Backend (NestJS):** สมองกลส่วนกลาง ทำหน้าที่รับคำสั่งจาก Frontend ตรวจสอบความถูกต้องและคิดเลข
3. **Database (PostgreSQL):** โกดังข้อมูลเก็บ 27 ตาราง (สต็อก, บิล, ลูกค้า, เงิน)
4. **Redis & BullMQ:** โต๊ะวางของด่วน ช่วยให้ระบบทำงานเร็วปานสายฟ้าแลบ และสายพานส่งงานเบื้องหลัง
5. **Multi-Tenant (มัลติเทแนนต์):** แปลง่ายๆ คือ **"ระบบหอพัก"** — เซิร์ฟเวอร์มีชุดเดียว แต่ให้ร้านค้าเช่าได้ 100 ร้าน โดยร้าน A ไม่มีทางแอบเปิดดูข้อมูลของร้าน B เด็ดขาด!

## 🚦 ภาค 2: ทำไมต้องแตกงานเป็น 40 Tickets? แล้วทำไมต้องแบ่งเป็น 3 Lane?

ถ้าปล่อยให้พวกเรา 3 คนเดินเข้าไปแล้วบอกว่า *"เฮ้ย มารุมเขียนโค้ดร้านค้ากันเถอะ"* สิ่งที่จะเกิดขึ้นคือ:
- ทุกคนแย่งกันแก้ไฟล์เดียวกัน
- พอจะกดรวมโค้ด (Merge) โค้ดชนกันระเบิดเป็นโกโก้ครั้นช์ (Merge Conflict)
- ไม่มีใครรู้ว่างานไหนต้องทำก่อน-หลัง

อาจารย์ก็เลยตั้งกฎเหล็กขึ้นมาว่า:  
👉 **"ทุกคนในทีม 3 คน ต้องได้แตะครบทั้ง 3 สาย: Frontend + Backend + CI/CD"**

งานประมาณ 40 ตัวจึงถูกจัดกลุ่มเป็น **3 เลน (3 ทีม)** ทำงานคู่ขนานกันเหมือนกองทัพ 3 เหล่า:

```
[Team 1 / Lane A]  💰 แก๊งการเงิน & แคชเชียร์      (NuimanLP)
[Team 2 / Lane B]  📦 แก๊งคลังสินค้า ทะเบียน & รายงาน (LomerAlloys)
[Team 3 / Lane C]  🛡️ แก๊ง รปภ. คุมประตู & ช่างเทคนิค (PattaraponKitcharoen)
```

| **#4** | **บัตรคล้องคอ & ยามตรวจบัตร** (`JWT Auth & TenancyGuard`) | ระบบล็อกอิน: ใครล็อกอินผ่านจะได้ "บัตรเวทมนตร์" (JWT Token) ที่แปะป้ายว่า *"กูคือพนักงานร้านศรีสุราษฎร์ฯ"* ทุกครั้งที่ส่งคำขอ ยามจะเช็คบัตรนี้เสมอ |
| **#6** | **ลงทะเบียนเครื่อง & ยศพนักงาน** (`Device Roles`) | แบ่งแยกระหว่าง **"เครื่องแคชเชียร์หน้าร้าน (pos)"** กับ **"คอมหลังบ้าน (backoffice)"** เครื่องหลังบ้านห้ามกดขายของเด็ดขาด! |
| **#31** | **กระดานโพสต์อิทตอบด่วน** (`Redis Cache Module`) | เอา Redis มาทำเป็นแคช อะไรที่ถามบ่อยๆ (เช่น รายชื่อสินค้า) แปะไว้บนไวท์บอร์ด ตอบกลับได้ใน 0.001 วินาที ไม่ต้องวิ่งไปขุดสมุดบัญชี |
| **#33** | **เครื่องดักจับคนกดสแปม** (`Rate Limiting`) | มีใครแกล้งยิงบอทรัว 1,000 ครั้ง/วิ ไหม? ถ้ามี เตะตัดขาตอบ Error `429 Too Many Requests` ทันที ป้องกันเซิร์ฟเวอร์ล่ม |
| **#34** | **สร้างสายพานส่งงานหลังบ้าน** (`BullMQ Infra`) | วางระบบคิวงาน อะไรที่หนักๆ และลูกค้าหน้าร้านไม่ต้องยืนรอ โยนลงสายพานนี้ |
| **#35** | **คนงานกะดึกแบกหาม** (`Background Worker Jobs`) | คนงานที่คอยหยิบงานจากสายพานไปทำตอนดึก เช่น ประมวลผลยอดขายลึกๆ หรือจัดระเบียบข้อมูล |
| **#36** | **เครื่องดูดข้อมูลย้ายบ้าน** (`Tenant Export Job`) | ถ้าร้านค้าบอก *"กูจะเลิกใช้ระบบมึงละ ขอข้อมูลร้านกูคืน"* กดปุ่มนี้ มันจะดูดข้อมูลทั้งร้านบีบเป็นไฟล์ Zip โยนคืนให้เขาไปอย่างปลอดภัย |
| **#37** | **ปล่อยฝูงซอมบี้ถล่มเซิร์ฟเวอร์** (`k6 Load Test`) | เอาบอท 200 ตัวมายิงซื้อของพร้อมกันเพื่อพิสูจน์ว่า: เซิร์ฟเวอร์ไม่พัง, สต็อกไม่เบิ้ล, และของไม่ติดลบ |
| **#38** | **หุ่นยนต์ตรวจการบ้านหลังบ้าน** (`Server CI Workflow`) | ระบบตรวจโค้ดอัตโนมัติบน GitHub: เช็ค Lint, รัน Unit Test, เปิดเครื่องเทสต์ยิงจริง ถ้าไม่ผ่านห้ามส่งงาน |
| **Frontend** | **หน้าล็อกอิน & ผูกเครื่อง** | ทำหน้าจอใส่ Username/Password, จอตั้งค่าผูกเครื่อง POS, และกล่องแจ้งเตือน Error ภาษาไทย |

## ⏳ ภาค 4: เส้นทางวิกฤต (Critical Path) — ใครห้ามอู้? ลำดับโดมิโนล้ม

งาน 40 ใบนี้ **ไม่ได้เริ่มพร้อมกันตั้งแต่วันแรกได้ทุกคน** เพราะมันเหมือนการสร้างตึก:

```
[ขั้นที่ 1: ตั้งเสาเอก]
  #14 (Team 3) ── สตาร์ทตู้คอนเทนเนอร์ (Docker / Nginx / Postgres / Redis)
       │
       ▼
[ขั้นที่ 2: เทปูนสร้างห้อง]
  #15 (Team 2) ── สั่งสร้างตาราง 27 ห้องในฐานข้อมูล + ติดตั้งระบบ RLS
       │
       ▼
[ขั้นที่ 3: จ้างยาม & ติดกลอนประตู]
  #4 & #6 (Team 3) ── ระบบล็อกอิน (Auth JWT) + บัตรประจำตัวเครื่องแคชเชียร์
       │
       ▼
[ขั้นที่ 4: เปิดร้านขายของได้!]
  #18, #19, #20 (Team 1) ── เครื่องคิดเงิน, ปั๊มเลขบิล, บัตรคิวกันเบิ้ล
```

> ⚠️ **จุดตายของโปรเจกต์:**  
> **`#14 ➡️ #15 ➡️ #4 ➡️ #6` คือ "เส้นทางวิกฤต (Critical Path)"**  
> ถ้า Team 3 ยังไม่เปิดตู้ (#14) หรือ Team 2 ยังไม่สร้างตาราง (#15) ... Team 1 จะนั่งตบยุง เพราะไม่มีที่ให้บันทึกเงินขายของ!
