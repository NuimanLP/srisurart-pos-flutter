## 2. เกือบกลับมติ k6 — บันทึกไว้เพราะมันเกือบเกิด

ตอนแรกเลือก **(a) ยกเว้น IP เครื่องยิงออกจาก `perip` ใน `nginx.conf`** เพราะมันแก้ปัญหาที่แท้จริงของ
#184: ต้องนัดคนสามคนพร้อมกัน ซึ่งไม่เคยเกิดขึ้นเลย

แล้วพบว่า `03_ARCHITECTURE.md §8.1` มีมติลงวันที่ **2026-09-15** เขียนไว้ชัดว่า
*"ไม่มีข้อยกเว้นให้ `perip`"* และมีโค้ดลงไปแล้วทั้งชุด — `--web.enable-remote-write-receiver`,
`location /prometheus-remote-write/` + allowlist + Basic Auth, `htpasswd-gen`,
`K6_REMOTE_WRITE_BASIC_AUTH_*`, `k6/lib/shard.js` ⇒ **การเลือก (a) คือการกลับมติที่มีของเสร็จแล้ว
ไม่ใช่การเติมช่องว่าง** จึงยกเลิก

เหตุผลที่ไม่เอา (a) ไม่ใช่แค่ "ของทำไปแล้ว" อีกสองข้อ: carve-out ที่เปิดค้างบน production เป็นความ
เสี่ยงถาวรแลกความสะดวกรอบเดียว · และต่อให้ยกเว้นแล้ว "1 IP ยิงผ่าน edge ที่ปิดตัวจำกัดของตัวเอง"
ก็ไกลจากทราฟฟิกจริงมากกว่า 3 IP จริง

## 3. 🔴 ผลค้นคว้าหักล้าง "BeeStation + SFTP"

บันทึกเต็มพร้อมลิงก์ต้นทางทุกข้ออ้าง: [`research-363-sftp-nas-offsite.md`](research-363-sftp-nas-offsite.md)

**BeeStation ไม่มี SFTP/SSH ให้ใช้** — รัน **BSM ไม่ใช่ DSM** สเปกซอฟต์แวร์ทางการระบุบริการไฟล์แค่
SMB2 / SMB2-large-MTU / SMB3 + เว็บ/แอป · SSH ที่มีคือช่อง diagnostic ของ Synology Technical Support
ที่หมดอายุเองใน 14 วันและ credential มีไว้ส่งให้ Synology — ห้ามใช้กับ cron

ทางไปต่อ **2 ทาง ทั้งคู่ไม่ต้องแก้ `backup-db.sh` แก้แค่ `rclone.conf`**:
1. ใช้ BeeStation เดิม → เปลี่ยน backend เป็น **`smb`**
2. ยืนยันจะเอา SFTP → ต้องใช้ NAS ที่เป็น **DSM (DS-series)** · BeeStation อัปเกรดข้ามไม่ได้ คนละ OS

**ข้อที่ยังไม่มีคำตอบและใหญ่กว่าเรื่องโปรโตคอล:** เส้นทางเน็ตจาก `mob04` (คณะ) ไป NAS (ร้าน)
ทางที่ไม่พึ่ง HTTPS/443 เลี่ยง SSL deep inspection ได้โดยโครงสร้าง ส่วน Tailscale ที่ control
plane/DERP วิ่งบน HTTPS **น่าจะ**ชนกำแพงเดียวกับ `ghcr.io` — **อนุมาน ยังไม่ได้ทดสอบ**
ยังไม่ยืนยัน: `mob04` ออกเน็ตได้แค่ไหน · เน็ตที่ร้านติด CGNAT ไหม (ถ้าติด port-forward ตาย)
