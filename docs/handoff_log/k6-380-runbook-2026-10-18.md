## 3. คำสั่งต่อเครื่อง (รันทั้งสามเครื่องพร้อมกัน ทีละ scenario — ห้ามใช้ `run-shard-test.sh` สำหรับรอบจริง ดู ticket-184 §5.3)

เตรียมครั้งเดียวต่อเครื่อง (เปลี่ยน `i` และ `MACHINE`; รหัสพิมพ์เอง **ห้ามใส่ลง chat/doc**):
```bash
cd server
export TESTID=<ค่าเดียวกันจากข้อ 2>
i=1;  export MACHINE=peter-mac        # เครื่อง 2: i=2 MACHINE=debian · เครื่อง 3: i=3 MACHINE=nui-meme
read -rs -p "k6 remote-write password: " RWPW; echo
export K6_PROMETHEUS_RW_SERVER_URL="https://k6:${RWPW}@172.30.58.20/prometheus-remote-write/api/v1/write"
unset RWPW
export K6_PROMETHEUS_RW_TREND_STATS="p(95),p(99)"
export K6_PROMETHEUS_RW_INSECURE_SKIP_TLS_VERIFY=true     # ใช้ได้กับ CA ส่วนตัวของ VM (ยืนยันแล้ว 10-05)
shot() { SHARD=$i/3 k6 run -o experimental-prometheus-rw --insecure-skip-tls-verify \
  --tag testid="$TESTID" --tag machine="$MACHINE" "$@"; }
```
🔴 รูป URL ถูกต้องเป๊ะ: `https://k6:<pw>@172.30.58.20/prometheus-remote-write/api/v1/write` — ไม่มี `/` หลัง `k6` ไม่มี `/` ท้าย (รอบก่อนพิมพ์ `https://k6/:…/write/` → `lookup k6: no such host`) · รหัสผิด = 401 แต่ **k6 ยัง exit 0** → ต้องตรวจในข้อ 4 ว่าข้อมูลเข้า Prometheus จริง

**เริ่มพร้อมกันด้วยเวลา epoch** (ตกลง `START` เป็น epoch วินาทีเดียวกันทั้งสามเครื่องผ่านแชต, เผื่อ ≥ 60 วิ):
```bash
wait_for() { while [ "$(date +%s)" -lt "$1" ]; do sleep 0.2; done; }
START=<epoch>; wait_for "$START"
```
ลำดับ (ทีละบรรทัด; **รอทั้งสามเครื่องจบบรรทัดก่อน** แล้วตกลง `START` ใหม่):
```bash

shot test/k6/02-write-sales-contention.js                          # 200 คนรวม (TOTAL_CONTENDERS=200 → 67/67/66)
#   → ทันที ก่อน re-seed ใด ๆ: coordinator รัน k6:verify (ข้อ 5) — ห้าม seed ซ้ำระหว่างนี้
```
