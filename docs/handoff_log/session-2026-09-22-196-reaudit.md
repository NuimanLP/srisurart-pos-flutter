## 4. สิ่งที่รอบ review จับได้ — บันทึกไว้เพราะเป็นความผิดของรอบตรวจเอง

รอบ review ตั้งโจทย์ให้หา "จุดที่ audit ใจดีเกินไป" และจับได้ 3 blocker **ก่อนโพสต์**:

1. **ตัวเลขที่แต่งขึ้น** — ร่างแรกเขียนว่า title-only ซ่อน PR ปิดใบ "~30%" **ไม่มีใครวัดตัวเลขนั้น**
   ของจริง 4/201 = 2% · ตัวการจริงคือ PR ที่ไม่ใส่ keyword เลย ~46% · session หลักยกตัวเลขของ agent
   มาใช้โดยไม่ตรวจ — นี่คือความผิดพลาดแบบเดียวกับที่ทั้งรอบนี้พยายามแก้
2. **กล่าวหาผิด** — ร่างแรกเขียนว่า #194 "ปิดก่อนงานเสร็จ เหมือน #184" ของจริง PR #327 (+780/−10)
   ส่ง AC หลักครบ และใบถูกปิด **64 วินาที** หลัง PR merge พร้อมคอมเมนต์ไล่ทีละ AC ⇒ ไม่ใช่กรณีเดียวกับ #184
   🔴 บทเรียน: ไฟล์พวกนี้เพื่อนร่วมทีมอ่าน อย่าเขียนประโยคพาดพิงคนโดยไม่ตรวจนาฬิกาให้ครบ
3. **อ้าง ADR ผิด** — ร่างแรกอ้าง ADR-0003 ว่าเป็นที่มาของข้อกำหนด `GET /products` + `POST /sales`
   **ADR-0003 §5 ไม่ระบุ endpoint ใดเลย** ข้อกำหนดนั้นมาจาก AC ของ #294 เอง
4. (should-fix) ร่างแรกใส่ ⚠️ ว่า #229 อาจครอบไม่ครบ — review ไปอ่านโค้ดแล้วพบว่า**ครบตามสเปก** และ
   ⚠️ นั้นต่างหากที่ทำให้เข้าใจผิด: `08 §6.2` ระบุว่ามีแค่ลูกค้าที่เข้าคิว ที่เหลือ**ปิดปุ่มตอน Degraded**
