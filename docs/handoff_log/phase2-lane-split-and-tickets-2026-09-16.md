## 3. รอบ `/scrutinize` — สิ่งที่เกือบหลุดลงไปใน AC ทั้ง 35 ใบ

ตารางเต็มอยู่ที่ `09 §11` · ที่สำคัญที่สุด 5 ข้อ:

1. 🔴 **Drift schema มีสองเจ้าของ** — A/18 (v7) กับ B/8-c, 10, 11-c, 13b ชน `database.dart` + `database.g.dart` ไฟล์เดียวกัน และทุกใบต้อง regenerate ไฟล์ 12k บรรทัดเดียวกัน → ย้าย 18 ไป B + กติกา "หนึ่ง PR หนึ่งเวอร์ชัน rebase ก่อน merge"
2. 🔴 **AC ของ 20-client รอ PR ของ lane C** — fixture `sync-push/*.json` เคยเป็นของ C ที่ซ่อนลึก 3 ใบ ทั้งที่กติกาบอกว่าสองฝั่งต้องอ่าน**ไฟล์ชุดเดียวกัน** → fixture ย้ายมาเป็นของ A ใน `0d`
3. 🔴 **`SyncFacade` ไม่พอ** — ไม่มี `payload` ที่ `08 §14` สั่งให้แท็บ "ถูกปฏิเสธ" โชว์ · และ `0d` ส่งแต่ abstract + fake แปลว่าหน้าจอของ C merge เข้า `main` แล้ว**เปิดไม่ได้**จนกว่า 8-client จะลง → `0d` ต้องส่ง `NullSyncFacade` ที่ใช้จริงและลงทะเบียนใน `repository_providers.dart` ด้วย
4. 🔴 **`requireManager` มี 20 จุดเรียก ไม่ใช่ 21** (+ 4 ตัวนิยาม + import) และ **`quotes.controller.ts:114` เขียน `role !== 'manager'` ด้วยมือ** — ใบที่สั่ง "ลบ 21 จุด" จะ grep แล้วเดินผ่านจุดนี้ (ทั้ง `08 §3` และร่างแรกของ `09` ผิดตรงกัน)
5. 🔴 **`CLAUDE.md` เขียนว่า fallback ใน `api_*.dart` มี 16 จุด ของจริง 22** — #229 ที่ยึดเลข 16 จะเหลือ fallback รอด 6 จุด (แก้บรรทัดใน `CLAUDE.md` แล้วในรอบนี้) → AC เปลี่ยนเป็น "contract test หาไม่เจอ" ไม่ใช้ตัวเลข

นอกจากนั้น: ใบ 6 ไม่มี AC เรื่อง RLS ทั้งที่ `schema.e2e-spec.ts` ตรวจเฉพาะตารางที่อยู่ใน `TENANT_SCOPED_TABLES` · `backup.controller.ts:91` เป็น `GET /backup/jobs/:id` คนละ route กับ export · ใบ 1 ตกหล่น `idempotency-routes.spec.ts` / `ROLES_THAT_MAY_VOID` / `InitialSchema.ts:57` · §7 ลากเส้น lane C เป็นอนุกรมทั้งที่แตกขนานได้ · 8-c ต้องรอ 4-c (payload พกเลข) · 20-s ต้องรอ 11-s (`sale.void_offline` อยู่ใน "push ทุก type")
