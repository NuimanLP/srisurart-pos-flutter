## 2. 🔴 สอง branch ที่ถือเอกสารไว้เป็นสำเนาเดียวในโลก

`research/production-host` และ `research/pwa-offline-shell` — **ไม่เคยเปิด PR ไม่เคย merge**
แต่ถือ `docs/research/production-host.md` (158 บรรทัด) และ `docs/research/pwa-offline-shell.md`
(266 บรรทัด) ที่**ไม่มีอยู่บน `main` เลย** ซ้ำร้าย #241/#242 ปิดไปแล้วและคอมเมนต์ปิดใบ**ลิงก์ตรงไป
ที่ไฟล์บน branch** ⇒ ลบ branch = เอกสารหาย + ลิงก์ในใบเสียพร้อมกัน

คำสั่งที่ใช้ตัดสิน — ใช้ซ้ำได้ทุกครั้งที่จะล้าง branch:

```bash
git merge-base --is-ancestor "$b" origin/main   # merged แล้วหรือยัง (ไม่ใช่ดูชื่อ ไม่ใช่ดู PR)
git log --all --diff-filter=A -- 'docs/research/*'   # ไฟล์นี้เกิดที่ commit ไหนบ้าง
```

อันที่สองคือตัวตัดสินจริง: มันบอกว่าไฟล์ถูก **เพิ่ม** ที่ commit เดียวบน branch นั้น ๆ เท่านั้น

**ทางแก้:** cherry-pick ทั้งสอง commit ขึ้น branch ใหม่ (คง author เดิมไว้ ไม่แตะเนื้องานวิจัย) →
เติมแบนเนอร์สถานะ → PR #386 → CI ผ่าน → merge `311703d` → **แล้วค่อยลบ branch**

🔴 **แบนเนอร์ไม่ใช่พิธีกรรม** — merge เอกสารเก่าเข้า `main` เฉย ๆ คือการสร้างเอกสารที่โกหก:
`production-host.md` เสนอให้ย้ายไปคลาวด์ ซึ่ง**เจ้าของตัดสินตรงข้ามไปแล้วตั้งแต่ 2026-09-15**
(host = `mob04`, environment เดียวและมันคือ production) และหัวข้อ "#67 angle" ในเอกสารก็เน่า —
#67 ปิดแล้ว และตัวบล็อก CD จริงวันนี้คือ FortiGate ที่ `ghcr.io` ไม่ใช่การไม่มี public IP
เหตุผลเดียวที่เก็บไว้คือคอมเมนต์ปิด #242 สั่งเก็บไว้เองเป็น input ของเฟสที่ร้านเข้าถึงจากนอกคณะ
